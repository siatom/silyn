## Scope

Make Silyn operable by someone other than its author:

- English `README.md` with invariants, quickstart, experiment command, safety
  note and license;
- `docs/security.md` (trust boundaries, capabilities, cancel file, secrets,
  sealed suite, reporting);
- `docs/operations.md` (backup/restore, retention, policy rollback, kill/resume,
  `Indeterminate` resolution, log locations, local-only assumptions);
- `docs/experiments/template.md` (identity, suite, budget, per-arm results,
  paired comparison, verdict, reproduction);
- `docs/architecture/observability.md` (planned span names, fields and
  redaction rules);
- `xtask verify-docs` and 12 unit tests for the docs and CI gates;
- a three-platform CI matrix with the full gate sequence.

Phase B (tracing spans and redaction tests) is **W7-03b** and is not part of this
gate. No crate source, migration, schema, suite or `Cargo.toml`/`Cargo.lock` file
was modified.

## Docs gate (`cargo run -p xtask -- verify-docs`)

The gate is intentionally literal and offline:

1. `README.md` exists, starts with a level-1 title, and contains
   `## Quickstart`, `## Security` and `## License`.
2. `docs/security.md`, `docs/operations.md`, `docs/experiments/template.md` and
   `docs/architecture/observability.md` exist and contain the section anchors an
   operator needs.
3. Every markdown link in the README and `docs/**` resolves, except external
   (`http`, `https`, `mailto`) and pure-anchor links. Links inside fenced or
   inline code are ignored so command examples cannot trip the gate.
4. No shipped document links to `docs.local/**`.
5. No shipped document contains an unresolved `TODO` or `TBD` word.
   `docs/agents/tasks/**` is excluded: those are internal task packages that
   discuss the rule itself.

The gate never reads the network and never needs a database.

## CI matrix

`.github/workflows/ci.yml` runs one job per platform:

| Runner | Toolchain | Steps |
|---|---|---|
| `windows-latest` | Rust 1.99.0 (stable, pinned) | fmt check, clippy `-D warnings`, workspace tests, release build, `verify-docs`, `verify-acceptance`, `verify-schemas`, `verify-migrations`, `verify-arch`, `verify-eval-integrity`, CLI version + doctor smoke |
| `ubuntu-latest` | same | same |
| `macos-latest` | same | same |

- `Swatinem/rust-cache@v2` caches the cargo registry and target directory.
- `fail-fast: false`, so one platform cannot hide another platform's failure.
- The workflow uses `permissions: contents: read`, contains no `secrets.*`
  reference, and never calls a model provider. The formal experiment (W6) runs
  locally with an operator-supplied key.

## Known gaps

- **Telemetry is W7-03b.** `docs/architecture/observability.md` is a frozen
  design contract, not an implementation. The current build has no tracing
  subscriber, no log file and ignores `SILYN_LOG_LEVEL`; the event journal and
  tool ledger are the durable observability surface.
- **README claims are pending W6.** The README states the status honestly: no
  measured improvement is claimed before the W6 report. The experiment section
  points at the template and the sealed command; it does not publish numbers.
- **Commands marked planned are not implemented.** `silyn run` (W3-03),
  `silyn evolution ...` (W5-03) and the HTTP API (W7-01) are documented only as
  contracts with the wave that delivers them. The README says `silyn run`
  currently exits 5.
- **The docs gate is not a prose review.** It checks anchors, links and markers;
  it cannot detect an inaccurate sentence. Human review still owns correctness.
- **No OS sandbox.** The security and operations docs repeat the W5-01 limit:
  evaluation isolation is process-level (cleared environment, fresh working
  directory, timeout), and a worker can still read the filesystem.
- **macOS arm64 locally unverified.** The matrix targets `macos-latest`; no local
  macOS machine was available for this task.

# W3-03 gate: CLI run/resume integration

- Wave: 3
- Date: 2026-10-21
- Status: **passed locally on Windows**

## Scope

The operator path from the shell to the runtime loop:

- `silyn run --task <task-id> [options]`
- `silyn run --session <session-id> --objective <text> [options]`
- `silyn run --resume <run-id> [options]`

This task wires W3-01 (loop) and W3-02 (events, ledger, cancel file) together and
keeps the existing `runs list|show|events|tools|cancel` surface unchanged.

### Runtime addition (minimal)

`Runtime::create_run(task_id, &RunOptions) -> RunRecord` was added so the app
knows the run id before execution starts and can pass
`<home>/run/<run_id>.cancel` through `RunOptions::cancel_file`. `run_task` now
delegates to `create_run` and then `execute`; loop, budget, ledger and
checkpoint semantics are unchanged. `RunOutcome` derives `Serialize` so the CLI
can print it as one JSON object.

### App service

`crates/silyn-app/src/runtime_service.rs`:

```rust
pub struct RunRequest {
    pub task_id: Option<TaskId>,
    pub session_id: Option<SessionId>,
    pub objective: Option<String>,
    pub resume: Option<RunId>,
    pub options: RunOptions,
    pub offline: bool,
}

impl App {
    pub async fn run(&self, request: RunRequest) -> Result<RunOutcome, SilynError>;
    pub async fn resume(&self, run_id: RunId, options: RunOptions) -> Result<RunOutcome, SilynError>;
    pub fn workspace_dir(&self) -> PathBuf; // <home>/workspace
}
```

`RunRequest::validate` is the single place for the source rules:

- exactly one of `--task`, `--resume`, or (`--session` + `--objective`);
- `--resume` cannot be combined with any other source;
- `--task` cannot be combined with `--session`/`--objective`;
- `--session` and `--objective` are only valid together;
- an empty objective is a permanent error.

Every violation is `SilynError::Permanent` -> exit 5, never a retryable error.

Provider and tool construction:

- `--offline`: `MockProvider` with one final response
  `{"action":"final","answer":"offline mock run"}`. It never reads an API key and
  never builds an HTTP client (tested with an unreachable base URL and a real
  key in the environment).
- otherwise: `ProviderConfig::from_env()` +
  `ReqwestTransport::new(config.timeout)` + `OpenAiCompatibleProvider`.
- tools: `ToolBroker::new(<home>/workspace, Arc::new(MemoryAuditSink))`; the
  workspace directory is created if missing.
- verifier: `AnswerVerifier` always returns `VerifiedOutcome::Unknown` with
  confidence `0.0` and no evidence refs. `RunSnapshot` does not carry the final
  answer, so W3 never claims success.
- default capabilities: **none**. `--capability` is repeatable, duplicates are
  dropped, and names are not validated up front: the broker remains the
  authorization boundary.

Run ordering in `App::run`:

1. validate the request (no storage access);
2. for `--resume`, reject unknown and terminal runs before provider work;
3. build provider/tools/verifier;
4. `--session/--objective` creates the task first;
5. `Runtime::create_run` (run id is now known);
6. set `cancel_file = Some(app.cancel_request_path(run_id))`;
7. `Runtime::execute` (or `Runtime::resume` for `--resume`).

## Command surface and exit codes

```text
silyn run [--task <id> | --resume <id> | --session <id> --objective <text>]
          [--offline] [--model <id>] [--max-steps <n>] [--max-wall-secs <n>]
          [--max-input-tokens <n>] [--max-output-tokens <n>]
          [--max-cost-usd <f64>] [--capability <name>]... [--json]
```

| Outcome | Exit |
|---|---|
| `Completed` | 0 |
| `Cancelled` | 3 (same code as a policy denial; both mean "not a success, not retryable") |
| `Failed` (budget, loop, indeterminate, model error) | 5 |
| Invalid CLI usage (clap: bad UUID, missing pair) | 2 |
| Unknown run/task, terminal run, conflicting sources, no source | 5 |

- `--json` prints the `RunOutcome` object on stdout:
  `{"run_id","status","outcome","final_answer","reason","steps","input_tokens","output_tokens","cost_usd"}`.
- Human mode prints `run:`, `status:`, `outcome:`, `steps:`, token/cost totals,
  `final_answer:` and, when present, `reason:`.
- A failed or cancelled *run* is a result, not a CLI error: the outcome goes to
  stdout and the exit code carries the class, so stderr stays empty.
- Invalid requests are rejected before `App::open`: `silyn run` with no source
  exits 5 and creates neither the home directory nor the database.
- `--model` defaults to `SILYN_LLM_MODEL`, else `deepseek-chat`.
- `--max-cost-usd` needs a configured price table
  (`SILYN_LLM_INPUT_PRICE_PER_M` + `SILYN_LLM_OUTPUT_PRICE_PER_M` via
  `ProviderConfig`); without one it is a permanent configuration error.
- `--offline` leaves the price unset, so `--offline --max-cost-usd` is a
  permanent configuration error (see deferred work).

Key assertions:

- `run --session ... --objective ... --offline --json` exits 0 with
  `status: completed`, `outcome: unknown`, `final_answer: offline mock run`;
  `runs show` reports `completed` with `started_at`/`finished_at` and the
  default model; `runs events` lists
  `run_created`, `run_started`, `run_verified` (`outcome: unknown`),
  `run_completed` in order.
- `--max-steps 0` exits 5, prints a `failed` outcome with
  `budget exhausted: step budget exceeded: step 1 > limit 0`, stores the run as
  `failed`, and the journal contains `run_failed` but no `run_completed`.
- Unknown `--resume` / `--task` exit 5 with a permanent error and create no run.
- A terminal run cannot be resumed (`already completed`, exit 5) and no second
  run appears.
- No source: exit 5 with
  `run requires exactly one of --task, --resume, or --session with --objective`
  and no database file.
- Offline runs never print `DEEPSEEK_API_KEY`, even when it is set and the base
  URL is unreachable.
- Cancel path: a service test injects a provider that blocks until a file
  appears in `<home>/run/`, discovers the run id via `App::list_runs`, calls
  `App::request_cancel`, and asserts the run ends `Cancelled`. Because that
  provider can only be unblocked by the run loop polling
  `<home>/run/<run_id>.cancel`, this proves `App::run` wired the documented
  cancel path.

## Deferred work

- **Real process kill**: cancellation is proven by a blocking in-process
  provider plus the file signal. Killing the process mid-step and asserting
  recovery from the ledger is a W3-01/W5 harness, not a CLI test.
- **Live event streaming**: `runs events` lists persisted journal rows; there is
  no SSE/tail mode yet.
- **Persistent audit sink**: the broker writes to `MemoryAuditSink`, so tool
  decisions are not persisted and the JSON outcome does not expose an audit
  count. The `audit_events` table lands with the later observability work.
- **W4 verifier**: `AnswerVerifier` is deliberately `Unknown`; no run can report
  `Success` yet.
- **Offline pricing**: `--offline` never builds a `ProviderConfig`, so it has no
  price table and `--offline --max-cost-usd` is a permanent error. A price-only
  accessor in `silyn-llm` would remove that limitation without duplicating env
  parsing.
- **Agent binding**: `--session` still resolves its agent through the session;
  runs do not pin an agent/profile version beyond the placeholder policy
  version created by `Runtime::create_run`.

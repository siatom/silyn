# W6-01 gate: real model solver and declared A/B/C contexts

- Wave: 6
- Date: 2026-10-21
- Status: **passed locally on Windows**

## Scope

Adds the piece W6 needs before the first paid run: a solver that actually calls a
model, and a declared context contract that makes the A/B/C comparison
reproducible.

- `ArmContext` (v1) — `memory`, `policy`, `provenance`; a closed JSON file, bounds
  checked, control characters refused, API-key-shaped strings refused, stable
  sha256.
- `ModelSolver` — synchronous `Solver` over the async `ModelProvider`, with a
  stored tokio runtime, a per-call timeout, exactly-one-JSON parsing, metered cost
  from `Price`, and errors scrubbed of keys, prompts and CSV.
- `Evaluator::run_matrix_with` / `run_sealed_matrix_with` with `ArmSolvers` — one
  solver per arm, the same budget/model/price and paired task order.
- CLI `--solver baseline|model` with `--context`, `--model`, `--base-url`,
  `--api-key-env`, `--max-tokens`, `--temperature`, `--in-process`.

Non-goals: the real DeepSeek run (W6 operator step), new suites or thresholds,
changes to `silyn-core`, `silyn-llm`, `silyn-storage`, migrations or other crates.
No frontend or schema changes.

## Context contract (`ArmContext` v1)

```json
{
  "memory": ["Check units before computing aggregates."],
  "policy": ["Always inspect the header before counting rows."],
  "provenance": {
    "memory_source": "silyn-memory:<agent-id>",
    "policy_version": "<uuid>",
    "notes": "free text, no secrets"
  }
}
```

- Arm A sees `memory = []`, `policy = []`; B sees memory only; C sees both. The
  CLI derives the three effective contexts from the single declared file.
- `deny_unknown_fields`: an extra key (`tools`, `api_key`, …) is a schema error,
  and all three top-level keys are required.
- Bounds: ≤ 20 entries per list, ≤ 2000 bytes per entry, ≤ 512 bytes per
  provenance string, ≤ 64 KiB for the file. Control characters are rejected.
- `provenance.notes` is optional; everything else must be non-empty.
- A string that looks like a vendor key (`sk-` plus 16+ token characters) or an
  `authorization: bearer` header is a `PolicyDenied` error, so a context file can
  never smuggle a secret into the statistics document.
- The effective context is hashed over its canonical JSON (fixed field order).
  `ArmContextRecord` carries `sha256` (effective), `source_sha256` (file on disk),
  entry counts and provenance; it is written per arm into the statistics JSON.

Context text is *data*: the prompt places it inside `<reference-notes>` with an
explicit statement that it cannot change the rules, tools, format or budget.

## Solver contract (`ModelSolver`)

- `ModelSolver::new(Arc<dyn ModelProvider>, model)` stores a
  `tokio::runtime::Runtime`; `Solver::solve` calls `block_on` with
  `tokio::time::timeout`. `futures::executor` is not used, so the provider keeps
  its tokio TLS/time context.
- System prompt = task rules + the arm's untrusted context block (absent for A).
  User prompt = objective + CSV. Every arm contains the CSV objective.
- Exactly one `Submission` object is accepted. A fenced `json` block is tolerated
  (some compatible providers wrap output anyway); trailing data, missing keys and
  non-JSON are `SilynError::Schema`, i.e. a task failure through
  `InProcessBackend`, never a panic.
- Errors never include the API key, the prompt, the CSV or the response body.
  Provider text is scrubbed (`sk-…`, `Bearer …`, `api_key=…`, registered secrets),
  truncated to 200 bytes on a UTF-8 boundary (below `TaskFailure`'s 240-byte cap)
  and prefixed with the error class.
- Cost uses `Price` and the token usage the provider reports; without a price
  table the solver spends 0.0 and the arm config records
  `price_configured = false`. The CLI replaces the evaluator's
  `price * attempts` estimate with the measured spend per arm
  (`ArmOutcome::with_cost_usd`), so the report shows metered cost.
- The provider's reported model id is kept (`reported_model`) and written to the
  report's `model_reported`; the configured model id stays in `model_id`.

## CLI

```text
silyn-eval run --solver baseline|model [--split train|dev|test] [--arm a|b|c|all]
               [--repeats 1-5] [--seed N] [--out report.json]
               [--stats-out report.stats.json] [--markdown report.md]
               [--manifest path] [--candidate-id uuid]
               [--context context.json] [--model deepseek-chat]
               [--base-url https://api.deepseek.com/v1]
               [--api-key-env DEEPSEEK_API_KEY] [--max-tokens N]
               [--temperature F] [--allow-sealed] [--in-process] [--timeout-ms N]
```

- `--solver model` requires `--in-process`; the subprocess worker keeps the
  deterministic baseline and never receives a key.
- `--solver model` with `--split test` still requires `--allow-sealed`, and the
  suite must be sealed with a matching `suite.lock`. The check runs before any
  provider configuration is read.
- `--context` is only read by `--solver model`; passing it to the baseline is a
  permanent error rather than a silent ignore.
- The key is read from the named environment variable and echoed nowhere; a
  missing or empty variable is reported by name only.
- Price table: `SILYN_LLM_INPUT_PRICE_PER_M` and `SILYN_LLM_OUTPUT_PRICE_PER_M`.
  Both must be set to meter cost.
- Baseline behavior, arguments and artifacts are unchanged.

## Isolation caveat

The model solver runs **in-process only**. It cannot use the subprocess worker:
the worker gets a cleared environment (so no API key), a fresh cwd and a
timeout, and would have to receive the prompt, the context and the key through
argv/stdin, which widens the exposure the isolation layer exists to remove. The
trade-off is documented rather than hidden:

- a model panic is contained by `InProcessBackend` (`catch_unwind`) and becomes a
  task failure, but a host-level fault (OOM, abort) would still take the harness
  down;
- the prompt and CSV live in the harness process for the duration of a call;
- W6 must record `backend = "in_process"` and state this caveat in the
  experiment report.

A model-in-subprocess design (worker receives a task, calls the provider itself,
key passed through a restricted environment entry) is future work and needs the
isolation contract widened by the Architect.

## Known gaps

- **No real provider run in this task.** W6 executes the sealed A/B/C experiment
  with the official endpoint, a hard budget and a pinned model; this task only
  makes that run possible. The real run still needs `DEEPSEEK_API_KEY`, the price
  table and `--allow-sealed`.
- **Price is per-token only.** `Price` has input/output cost per million tokens;
  cache-hit discounts or per-request fees are not modelled. The report records
  measured spend but cannot reconstruct the provider invoice exactly.
- **Provider-reported model is not enforced.** A gateway that silently routes to a
  different model is recorded in `model_reported` but not rejected; W6 must check
  the value against the pinned model before accepting the report.
- **Timeout is not covered by an offline test.** `ModelSolver` applies
  `tokio::time::timeout`, but `MockProvider`/`MockTransport` answer immediately and
  a delaying fake would need `async_trait` in the dev-dependency set. Covered by
  review, not by CI.
- **Prompt is single-turn.** There is no repair turn, tool loop or step budget in
  the model solver; `max_steps` remains a recorded budget field only. A malformed
  answer is one failed task, which is the pre-registered behavior.
- **Baseline subprocess path unchanged.** The W5 worker still hosts only
  `BaselineSolver`; `ModelSolver` is unreachable from `worker`.

# W2-03 gate: CLI and service layer

- Wave: 2
- Date: 2026-10-20
- Status: **passed locally**

## Scope

A storage-backed service layer in `silyn-app` and a scriptable `silyn` CLI over
it: `init`, `agent create|list`, `session create`, `task create`,
`runs list|show`, `run`, plus the existing `doctor` and `config`.

`App` owns the storage handle and the resolved home directory. It is the only
place that decides validation and default versions, so the future HTTP API
(W7) gets identical behavior.

## Command surface

| Command | Output | Notes |
|---|---|---|
| `silyn init` | `home:` / `database:` lines | creates the directory and applies migrations; idempotent |
| `silyn agent create --owner <name>` | bare agent id | trims the owner; empty owner is a usage error |
| `silyn agent list` | table (id, owner, profile, created) | newest first |
| `silyn session create --agent <id>` | bare session id | unknown agent is a permanent error |
| `silyn task create --session <id> --objective <text>` | bare task id | task starts in `created`; nothing is scheduled |
| `silyn runs list` | table (id, task, status, model, created) | newest 50; empty on a fresh database |
| `silyn runs show <id>` | key/value record | missing run is a permanent error |
| `silyn run` | none | always fails: runtime loop lands in W3 |
| `silyn doctor` / `silyn config` | unchanged | reports key presence only, never values |

Every command accepts the global `--json` flag. JSON shapes are the storage
records serialized with `serde`:

- `init`: `{"home", "database"}`
- `agent`: `{"id", "owner_id", "profile_version", "active_policy_version", "created_at"}`
  (`agent list` returns an array of these, newest first)
- `session`: `{"id", "agent_id", "context_version", "created_at"}`
- `task`: `{"id", "session_id", "objective", "status", "created_at", "updated_at"}`
- `runs list`: array of run records; `runs show`: one run record
- errors on stderr: `{"error": {"class", "message"}}`

Timestamps are RFC 3339 in UTC. Identifiers are UUIDv7 strings.

## Exit codes

| code | meaning |
|---|---|
| 0 | success |
| 2 | usage error (clap: unknown command, missing or malformed argument) |
| 3 | policy denied (`ErrorClass::PolicyDenied`) |
| 4 | transient failure (`ErrorClass::Transient`) |
| 5 | permanent failure (`ErrorClass::Permanent`, `ErrorClass::Storage`, `ErrorClass::Model`, `ErrorClass::Schema`) |

`ErrorClass::Indeterminate` maps to 5 as well: there is no dedicated retry code
and an unknown side effect must never be reported as success or as safely
retryable.

## Notes

- `silyn-storage` exposes single-row lookups but no list queries. `App` selects
  the ids with SQL and decodes each row through the storage repository, which
  keeps row decoding in one place. `runs list` is capped at
  `RECENT_RUNS_LIMIT` (50) so the extra round trips stay bounded; agents are
  few by construction and are listed without a cap.
- `App::open` creates the home directory for every command, so `agent list` on
  a fresh checkout initializes storage instead of failing.
- Agents and sessions carry placeholder versions (`profile-v1`, `ctx-v1`)
  until versioned profiles and the context builder land.
- `create_agent` takes an owner label; it is not authentication and must not be
  treated as an authorization decision.

## Scope

Implement the frozen tracing contract in
[`docs/architecture/observability.md`](../architecture/observability.md) for the
run loop, without breaking the no-subscriber build:

- `crates/silyn-runtime/src/telemetry.rs` owns the span names, the field
  constants, the redaction helper and the span constructors;
- `crates/silyn-runtime/src/run.rs` creates a `run` span per attempt, one `step`
  span per loop iteration, one `model` span per provider request, one `tool`
  span per tool execution or recovery, one `checkpoint` span per write and one
  `verify` span per verifier invocation;
- `tracing = "0.1"` is a normal dependency; `tracing-subscriber = "0.3"` is a
  dev-dependency for the collecting test layer only. The library installs no
  subscriber and has no exporter.

No migration, schema, journal, ledger, core, storage, app, CLI or eval-suite file
was modified. `Cargo.lock` only gains the tracing-subscriber subtree.

## Span contract

The six span names are a closed set; the constants are compared against the
document's tables by `span_names_and_fields_match_observability_doc`, so a doc
edit or a renamed constant fails the gate.

| Span | Parent | Fields attached by the runtime |
|---|---|---|
| `run` | root | `run_id`, `task_id`, `policy_version`, `model_id`, `status`, `step_count`, `input_tokens`, `output_tokens`, `cost_usd`, `duration_ms` |
| `step` | `run` | `run_id`, `step_id` (tool turns), `step_index`, `kind`, `status`, `duration_ms` |
| `model` | `step` | `run_id`, `requested_model`, `model_id`, `status`, `input_tokens`, `output_tokens`, `cost_usd`, `duration_ms`, `retry_count` |
| `tool` | `step` | `run_id`, `step_id`, `tool_name`, `capability`, `call_id`, `state`, `duration_ms`, `error_class` |
| `checkpoint` | `run` | `run_id`, `schema_version`, `checksum_prefix`, `direction`, `status` |
| `verify` | `run` | `run_id`, `outcome`, `evidence_count`, `duration_ms` |

Every constructor declares the complete field list from the contract and marks
unknown values as `tracing::field::Empty`, so an omitted value stays omitted
instead of becoming `0` or an empty string. The runtime never records
`agent_id`, `provider`, `checker` or `result_ref`: those values are not known at
the call site, and `result_ref` in the ledger holds tool output rather than an
opaque artifact id, so it must not be exported.

### Work-order shorthand

The task package names a subset of fields in shorthand. The constants stay
available, but emitted spans use the canonical names from the observability
document:

| Work order | Contract field used on spans |
|---|---|
| `step_seq` | `step_index` |
| `tool` | `tool_name` |
| `model` | `model_id` / `requested_model` |
| `latency_ms` | `duration_ms` |

`emitted_spans_declare_only_contract_fields` asserts the declared field set of
every emitted span, so the two lists cannot drift apart silently.

## Redaction

`redact(value)` runs before any string reaches a span field:

- removes `sk-...` keys, the token after `Bearer ` (case-insensitive), and the
  value of `api_key=`, `api_key:`, `DEEPSEEK_API_KEY=` including the quoted JSON
  form, replacing each value with `[REDACTED]`;
- truncates to at most 200 bytes on a UTF-8 boundary (`MAX_FIELD_BYTES`), so a
  multi-byte character is never split;
- leaves key-free text unchanged.

The module is an allowlist, not a denylist: only the constants above can be
attached, and the constructors never accept a message, argument, artifact or
`Debug` value.

## Instrumentation points

- `run`: created in `run_existing`, which serves `run_task`, `execute` and
  `resume`; records the entry status, then the terminal status, step count,
  tokens, cost and duration.
- `step`: `status` plus `duration_ms`; `kind` is `model` for a model turn and
  `tool` for a recovered pending action.
- `model`: one span per request (repair turns included), `retry_count` is the
  number of attempts after the first, and `model_id` comes from the provider
  response.
- `tool`: `state` moves from `started` to `succeeded`, `failed` or
  `indeterminate`; `error_class` is one of the four contract values.
- `checkpoint`: `checksum_prefix` is the first 12 hex characters of the stored
  checksum; `direction` is `write`.
- `verify`: `outcome` maps `VerifiedOutcome` to `success`, `failed` or
  `unknown`; a provider error records `unknown` and no message.

Never recorded: prompts, messages, objectives, memory summaries or ids, tool
arguments, tool output, file contents, absolute paths and raw error messages.

## Known gaps

- **No subscriber and no exporter ship with the library.** Spans are discarded
  unless a caller installs a subscriber; there is no OTel, file sink, sampling
  policy or `SILYN_LOG_LEVEL` wiring. That remains a follow-up for the CLI/API
  surface, and the default must stay local-only.
- **The contract document still says "planned".** The status line of
  `docs/architecture/observability.md` is owned by W7-03a; flipping it to
  implemented needs an integrator commit, which this task did not make.
- **Early errors are not attributed to a terminal status.** A failure before the
  session starts (missing task, invalid budget, checkpoint corruption) closes the
  `run` span with no `status`; the journal remains authoritative.
- **`step_id` is absent on model-only steps.** The runtime does not mint a step
  row for a model turn, so the field stays empty rather than carrying a made-up
  id.
- **`provider`, `checker` and `result_ref` are declared but never recorded.**
  There is no provider name on `RunOptions`, no verifier name on the trait and
  the ledger reference is tool content, not an artifact id.
- **Duration is wall-clock per span, not a histogram.** Metrics aggregation and
  sampling are out of scope for this task.

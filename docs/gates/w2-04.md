## Design notes

- **Determinism.** SplitMix64 seeded per `(split, index)`; no RNG crate. The
  generator emits LF-only CSV and formats floats with one decimal, so the same
  seed yields byte-identical text on every platform.
- **Oracle provenance.** The row model is built and the oracle is written before
  rendering; the CSV is never parsed back to produce ground truth. The
  `oracle_matches_generator_metadata` test re-derives counts with an independent
  parser to prove the two stay aligned.
- **Traps.** Unit mismatch, missing cells, duplicate copies, thousands
  separators, column-name drift, optional UTF-8 BOM and timezone offsets. Every
  task has at least one missing cell and one duplicate; the other traps are
  seed-selected and their coverage is asserted on the train split.
- **Sealing.** `SealedTestSet` stores tasks in a private field and only exposes
  `len`, `is_empty`, `digest` and `evaluate`. A source-level regression test
  fails if a task/oracle getter is added. `suite.lock` freezes `suite.toml` and
  `README.md`; fixtures are reproducible and intentionally not sealed.
- **Arms.** W2 runs A, B and C with the same solver because memory and evolution
  do not exist yet. The report says so through identical outcomes, and the
  verdict is `reject` (no measured gain). `decide` can never return `promote`:
  a passing run still requires the W5 policy gate (`await_approval`).
- **Baseline honesty.** `BaselineSolver` counts distinct rows, duplicate copies
  and empty cells mechanically but trusts the header for the unit. It scores
  7/10 on dev and returns parse errors as errors instead of inventing answers.
- **Stateless runner.** The W2 runner opens no database and writes only the
  `--out` report, so the temporary-database requirement is trivially satisfied;
  it becomes binding when the runtime is executed under evaluation (W5).

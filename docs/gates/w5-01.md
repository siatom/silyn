# W5-01 gate: evaluation lab

- Wave: 5
- Date: 2026-10-21
- Status: **passed locally on Windows**
- Task: `docs/agents/tasks/W5-01-eval-lab.md`

## Scope

Turned the W2 eval skeleton into a reproducible lab:

- sealed `csv-stats-v1.1` test split, reachable only through `SealedTestSet`;
- subprocess isolation per task (`silyn-eval worker`), with a cleared environment,
  a fresh temporary working directory/database path and a wall-clock timeout;
- A/B/C arms with one identical solver, model, task order, budget and price;
- repeated runs with a recorded seed;
- paired B−A, C−B and C−A gains with a deterministic 95 % percentile bootstrap;
- schema-valid JSON report plus a statistics companion and Markdown rendering;
- hash-locked suite artifacts.

## Command surface

```text
silyn-eval run --suite <id> --split train|dev|test --arm a|b|c|all
               [--repeats 1-5] [--seed N] [--out report.json]
               [--stats-out report.stats.json] [--markdown report.md]
               [--manifest path] [--candidate-id uuid]
               [--allow-sealed] [--in-process] [--timeout-ms N]
silyn-eval hashes [--manifest path]
silyn-eval worker [--fault none|panic|nonzero|garbage|sleep] [--diagnostics]
```

- `--split test` exits 1 with `PolicyDenied` unless `--allow-sealed` is passed
  **and** the manifest says `sealed = true`. The sealed path then verifies
  `suite.lock` before loading any task, so a tampered artifact also exits 1.
- `--arm` other than `all` runs a single arm for smoke checks and writes no
  artifacts; a report always needs the full matrix.
- `--in-process` is a debugging backend. The default and only CI path is the
  subprocess worker.
- `worker` is hidden from help. `--fault` and `--diagnostics` are test hooks; the
  CLI never sets them for a real candidate.
- `hashes` prints the computed split digests and exits non-zero when `suite.toml`
  records stale values.

## Isolation contract

Per attempt:

1. `std::process::Command` re-executes the current binary as `worker`;
2. `env_clear()`, then only `PATH`, `SYSTEMROOT`, `TEMP`, `TMP` (Windows) or
   `PATH`, `HOME` (Unix) are copied from the harness;
3. `current_dir` is a fresh `tempfile` directory; the task database path is
   `<cwd>/silyn-eval.sqlite`, so two attempts never share state and no extra
   environment variable is needed;
4. the task JSON is written to stdin and stdin is closed, so the worker cannot
   block waiting for more input;
5. the harness polls for `timeout_ms`; on timeout it kills and reaps the child;
6. non-zero exit (including a panic, exit 101), non-JSON stdout or a timeout
   becomes `TaskFailure` with a bounded detail and the run continues.

`InProcessBackend` exists for unit tests and wraps `catch_unwind`, so a panicking
solver is a task failure there too.

## Statistics and verdict

- Paired by task id; the delta per task is `candidate_rate − baseline_rate` in
  percentage points.
- Percentile bootstrap: 1000 resamples by default, confidence 95 %, SplitMix64
  with the fixed seed `0x5eedb00700000001`, so a fixed outcome set always
  produces the same interval. The bootstrap seed is independent of the run seed;
  re-rolling the interval to fit a conclusion is not possible without changing
  the recorded configuration.
- Degenerate inputs: empty sample, all-success and all-failure return a
  zero-width interval at the point estimate, never a panic. A constant sample
  short-circuits to `(point, point, point)`.
- Decision order (pre-registered in `suite.toml`):
  1. empty or unequal attempt counts → `invalid`;
  2. fewer than 2 paired tasks → `inconclusive`;
  3. any unauthorized action → `reject`;
  4. absolute cost cap (`max_cost_usd`) exceeded → `reject`;
  5. `C/B` cost ratio above `max_cost_ratio` → `reject`;
  6. `B − C` regression above `max_regression_pp` → `reject`;
  7. `C − A` below `min_gain_pp` → `reject`;
  8. `C − A` lower CI bound not above zero → `reject`;
  9. otherwise `promote`.

## Contract gap: report v1 has no statistics fields

`schemas/eval_report.schema.json` is frozen, closes the root object
(`additionalProperties: false`) and its `verdict` enum has no `inconclusive`.
The task package also requires durations, seeds, arm configuration, unauthorized
actions and paired confidence intervals in the report. Rather than mutate the
architect-owned schema or silently drop data, the runner writes two documents
from one run:

- `--out` — exactly `EvaluationReport` v1, validated field by field;
- `--stats-out` (default `<out>.stats.json`) — `EvaluationStatistics` v1 with the
  seeds, budgets, durations, per-arm unauthorized actions, suite digests,
  comparisons and the `inconclusive` detail;
- `--markdown` — rendered from those two documents only. A test parses every
  numeric token out of the Markdown and fails if one is absent from the JSON.

`inconclusive` is reported as `reject` in the schema document (an unproven
promotion is not a promotion) and as `inconclusive` in the statistics document.
Recommendation for the architect: add the statistics fields (or a
`statistics_ref`) to `EvaluationReport` v2 before W6 publishes results.

## Notes and limits

- **No OS sandbox.** Isolation is process-level: cleared env, fresh cwd, timeout
  and stdin/stdout only. A worker can still read the filesystem. A seccomp/Job
  Object sandbox is out of scope for W5 and must not be claimed in W6.
- **No candidate code path yet.** Workers run `BaselineSolver` for all three
  arms. W6 replaces A/B/C with real memory and policy arms; the fairness check
  (`ArmsConfig::validate_equal_budget`) and the worker protocol are already in
  place for that.
- **No OTel spans.** The statistics document records backend, durations and
  seeds, which is enough to audit a run; tracing is deferred to the observability
  workstream.
- **No JSON-Schema dependency.** The report contract is asserted field by field,
  including exact key sets to honour `additionalProperties: false`.
- **Timeouts are best effort.** The harness kills the worker process; a
  grandchild process would need platform job objects to be reaped as well.

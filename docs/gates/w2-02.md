# W2-02 gate: tool broker and sandboxed tools

- Wave: 2
- Date: 2026-10-20
- Status: **passed locally on Windows**

## Scope

Capability-gated tool broker plus four tools: `fs.list`, `fs.read`,
`data.profile` and `report.write`. Deny by default, path confinement to the run
root, and an audit record for every allowed and denied call.

## Notes

- Authorization is a plain string comparison against
  `AuthorizedToolContext.capabilities`; arguments and model text are never
  consulted.
- Path arguments are validated syntactically first (only `/` and `\` separated
  relative components, no `..`, no `:`, no leading separator) and then resolved
  with `dunce::canonicalize`. This makes the rules identical on Windows and Unix.
- `report.write` creates `output/` but not deeper directories; the parent of a
  report path must already exist and resolve inside the root.
- Audit detail contains the call id and capability or error text, never file
  content, so report bodies are not copied into the audit stream.
- `fs.read` does its own size check before and after reading, which also covers
  files that grow between the metadata call and the read.

## Deferred

- Idempotency ledger integration: the broker is a pure executor and does not
  depend on `silyn-storage` for the tool-call ledger. Wiring repeated calls to
  the prior result belongs to the W3 runtime loop, where the call id and step
  lifecycle are owned.
- Persistent audit sink: `MemoryAuditSink` is for tests and single-process runs.
  The append-only storage sink lands with the runtime audit wiring (W3/W5).
- Symlink escape test runs only on Unix (`#[cfg(unix)]`) because creating
  symlinks on Windows needs elevated privileges. The same canonicalization check
  rejects Windows junctions and symlinks, but that path is not exercised by the
  local Windows test run.
- Directory-listing symlink entries are reported by name only; entry types are
  not included in the tool result.
- Filesystem work runs inline in the async executor. Reads are capped at 1 MiB,
  but `data.profile` streams the CSV and keeps unique rows in memory; moving the
  tool calls to `spawn_blocking` belongs with the runtime executor (W3).
- Report writes are not atomic; a crash mid-write can leave a partial file.

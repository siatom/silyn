# W4-02 gate: evidence-based verifier and provisional experiences

- Wave: 4
- Date: 2026-10-21
- Status: **passed locally**

## Scope

A pluggable `OutcomeVerifier` whose checkers only inspect run artifacts, plus a
deterministic experience extractor that turns verified runs into provisional
lessons. Migration `0004_learning.sql` adds `experiences`,
`experience_evidence` and the partial unique index that keeps at most one active
lesson per agent and normalized text.

Non-goals: model self-assessment, reflection, policy candidates, promotion
(W5) and context injection (W4-03).

## Contracts

- `CheckResult` — `Success { evidence }`, `Failed { code, reason, evidence }`,
  `Unknown { reason }`.
- `Checker` — `async fn check(&self, run: &RunSnapshot, artifacts: &ArtifactSet)
  -> Result<CheckResult, SilynError>`.
- `ArtifactSet` — `new(root, refs)`, `get(reference)`, `all()`, plus `len()`
  and `is_empty()` for callers.
- `CompositeVerifier` — `new(checkers)`, `with_policy(policy)`, plus the
  additive `with_artifact_root(root)` builder needed for `file:` references
  (the frozen `OutcomeVerifier::verify` signature has no root argument).
- `VerificationPolicy` — `AnyFailureFails` (default), `AllMustSucceed`.
- `ExperienceRecord` / `EvidenceStatus` / `ExperienceStatus` / `ExperienceStore`
  — `extract`, `list`, `confirm`, `retire`.

`RunSnapshot` and `silyn-core` are unchanged. `silyn-storage`, `silyn-runtime`,
`silyn-app`, `silyn-cli`, `eval/suites/**`, `Cargo.toml` and migrations
`0001`–`0003` were not touched.

## Rules implemented

- **Success needs agreement.** Every checker must return `Success` for the run
  to be `Success`; the merged evidence of every checker is carried on the
  result. One checker is enough to succeed only if it is the only checker.
- **Failure dominates.** Every checker runs (no short-circuit), the first
  `Failed` supplies `code`/`reason`, and the evidence list merges every
  observed item. `Unknown` never becomes `Success`.
- **No checkers, no verdict.** An empty checker list is `Unknown` under every
  policy, never a vacuous success.
- **Artifact references.** `inline:<text>` is inline; `file:<path>` resolves
  inside `ArtifactSet.root` and is rejected when it is absolute, contains `..`,
  escapes the canonical root (including through a symlink), is not a regular
  file, is not UTF-8 or exceeds 2 MiB; a plain string is a file when it resolves
  and exists, otherwise inline content (W3 compatibility). Unreadable
  references are dropped, which surfaces as `Unknown`.
- **Expected answer.** The first artifact that looks like a JSON document is
  compared. Objects are subset-matched recursively, arrays and scalars match
  exactly, extra keys are allowed; a malformed document yields
  `Failed { code = "malformed_artifact" }` and a mismatch yields
  `Failed { code = "wrong_answer" }` with the JSON path in the reason.
- **File contains.** Any artifact containing the needle is `Success`; no match
  is `Failed { code = "missing_text" }`; no readable artifact is `Unknown`; an
  empty needle is `Failed { code = "invalid_checker" }` instead of a vacuous
  match.
- **No ambient capability.** Checkers read the supplied artifacts only. There
  is no model, network or shell call anywhere in `verifier.rs`.
- **Extraction.** `Unknown` returns `Ok(None)` and writes nothing. `Success`
  yields `Verified result using independent checks.` at confidence `0.4`;
  `Failed` maps the code through a fixed table (`unit_mismatch`,
  `missing_values`, `duplicate_rows`, `wrong_count`, `tool_error`, generic) at
  confidence `0.3`. Both are `provisional`.
- **Dedup.** The lesson is trimmed, whitespace-collapsed and lowercased; the
  active `(agent_id, normalized_lesson)` row is reused, one
  `experience_evidence` row is added per new run, a repeated run is a no-op, and
  `source_run_ids` is rebuilt from the evidence rows in one transaction.
- **Confirmation.** Needs at least two distinct evidence runs *and* at least one
  `success`; `unknown` evidence is stored but excluded. Otherwise a
  `SilynError::Permanent`. Confirmation sets `confirmed` and confidence `0.7`.
  Already-confirmed rows are idempotent; retired and rejected rows are refused.
- **Retirement.** `retired` withdraws the row; the partial unique index lets the
  same lesson be extracted again as a new active experience. Retiring an
  unknown id is permanent; retiring twice is idempotent.
- **Isolation.** `extract` refuses a run that belongs to another agent
  (`PolicyDenied`) or does not exist (`Permanent`); `list` filters by
  `agent_id`. `confirm`/`retire` take only an `ExperienceId` (frozen signature),
  so possession of the opaque id is the capability there; the record cannot be
  reached through another agent's `list`.

## Known gaps

- **One experience per lesson text per agent.** Extraction can only ever attach
  `failed` evidence to a failure lesson and `success` evidence to the fixed
  success lesson, so a *mixed* experience (failures plus a later success) cannot
  be produced by `extract` alone. Confirmation of a mixed row is implemented and
  tested by seeding an evidence row, but no caller writes one yet. Whether a
  later success should confirm the failure lesson, or open a new one, is a
  product decision for W5 reflection.
- **Unknown evidence is never written.** There is no API to attach `unknown`
  evidence, by design; the schema keeps the value for audit and the `confirm`
  filter excludes it.
- **`confirm`/`retire` carry no agent principal.** The frozen signature takes
  only `ExperienceId`. Isolation therefore relies on the caller holding the
  opaque id; an agent-scoped variant is an Architect contract change.
- **Artifact reads are synchronous** inside `ArtifactSet::new` (bounded to
  2 MiB per file). A run with hundreds of large artifacts would block the async
  worker for the duration of the read; a size/count budget belongs to the
  runtime call site.
- **`last_used_at` is never set.** There is no usage path until context
  injection (W4-03).
- **No schemas for the new contracts.** `schemas/` still has no
  `OutcomeVerifier`/`CheckResult`/`ExperienceRecord` JSON schema; adding one is
  Architect-owned and outside this package.
- **Deferred to later waves:** reflection (`W5-02`), policy candidates and
  promotion gates, candidate evaluation, and injecting confirmed experiences
  into prompts (`W4-03`).
